# Functional test cases

What a user can do in MyProfessionalMe, per feature and role, and which automated test checks it.

- Run the automated tests with `npm test`; `npm run test:coverage` adds a v8 coverage report (`coverage/`, git-ignored).
- Row-level security is out of scope here: `supabase/tests/rls.sql` (`npm run test:db`) checks it against the linked project.
- **Covered by** names a test as `file › describe › it`, with files relative to `src/`. **manual** means no automated test, with the reason.
- Tests never reach Supabase. `src/test/setup.ts` swaps the client for an in-memory fake (`src/test/fakeSupabase.ts`), and the view-model tests also mock `learnerStore` and `contentStore`.
- Most cases run against the view-model: `src/test/harness.ts` builds a `Logic` over a state, an access and a subject, and applies its `setState` patches. Screen tests (`*.test.tsx`) render with React Testing Library on jsdom.
- A case marked **bug** has an `it.fails` test. That test passes while the bug is there and fails once someone fixes it, so whoever fixes the bug turns it into a plain `it`.

**Roles:** Learner (any signed-in person viewing themselves), Counsellor (viewing a counsellee), Domain Admin (one or more business lines), General Admin (all content, no users), System Admin (everything), No line/stage (a person whose profile has no business line or career stage).

**Size:** 289 cases: 276 automated (7 of them documented bugs with `it.fails`, all fixed since; two edge-case rows point to the cases that cover them) and 13 manual. Every one of the 511 tests is named at least once below.
