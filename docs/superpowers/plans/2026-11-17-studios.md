# Studios Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the nine studios the v4 design shows next to the Flash card & Exam Studio: Avatar, Reel, Podcast, Game, Slides, Motion, Explainer, Job aid and Case. Reuse code and ideas from GameStudio, Horizon, Socials Reel Studio and Taxatar.

**Architecture:** One studio spine (`src/studioVals.ts` and `src/screens/Studios.tsx` from v4 Task 13) becomes data-driven:
- **Studio definitions.** Each studio is a definition: questions, an item schema, produce options, build steps and a preview kind.
- **What a studio makes.** Its output is a contribution that goes through the existing peer review and publishes into `learnings.content` (one new `kind` per studio).
- **Text.** All text AI goes through `complete()` and the `ai` edge function.
- **Media services.** Each sits behind its own edge function adapter, keyed through the existing AI connections (Vault, providers `elevenlabs` and `heygen`, use kinds `voice` and `avatar`).
- **Media files.** They go to one private Supabase Storage bucket.

**Tech Stack:** React 19, Vite, TypeScript, Supabase (Postgres, RLS, Storage, edge functions), Vitest, PGlite RLS runner.

**Spec:**
- The v4 design's `STUDIOS` block. Use its questions, items, rows and build steps per studio; names in examples become roles.
- The owner's answers of 17 Nov 2026:
  - Build the other studios, taking code and inspiration from the four projects (this reverses D1).
  - Voices: ElevenLabs with a browser-voice fallback, from an admin-approved list of stock voices.
  - Video: rendered in the browser.
  - Avatar practice: a live video avatar.
  - Order: cheapest first, one release per phase.

## Global Constraints

- All Global Constraints of `docs/superpowers/plans/2026-11-17-design-v4.md` apply:
  - Inline styles on tokens.
  - No fictional people; the design's Marleen, Pieter, Sara and Yves become roles: "HR director · 50s" and so on.
  - Honest UI; View as is read-only.
  - One permissive policy per table and action, an RLS case per policy, and mirrored TS/SQL rules with sync tests.
  - Files of about 250 lines at most (UI about 220); the v4 commit trailer.
- One AI path for text: `complete()` → `ai`. Media services each have one adapter edge function (`voice`, `avatar`); none falls through to another source silently. The browser-voice fallback is shown as such.
- No secret in the client: provider keys stay in Vault via AI connections; edge functions read them with `ai_connection_key()`.
- Every studio output carries "Made with AI" where AI made it (EU AI Act Art. 50 marking, as Taxatar's `X-AI-Generated`), and "Scripted" where it did not.
- Every studio's "Send for review" goes through the same contribution path as Flash cards (v4 Task 12), with the client-words check and creation rules. Contribution formats and `creator_rules.formats` grow per phase, TS and SQL together.
- Media limits (from the design): reel ≤ 90 s, podcast ≤ 30 min, motion ≤ 90 s, slides ≤ 15 min. Each TTS call ≤ 5,000 characters (chunk longer text).
- Migrations: new files only; never edit a pushed migration. Verify with PGlite; push to the live project with `supabase db push` at the end of each phase (owner's standing permission of 17 Nov 2026), then `npm run test:db` and advisors.

## Review Focus

1. **AI-generated SVG or game code carrying script or external loads.** Sanitised (SVG) or refused by the static scan, and sealed by CSP (games). Tests in Phases 2 and 4.
2. **A voice or avatar service is not configured or fails mid-way.** The studio says so and offers the fallback; nothing pretends to be the service. Tests in Phases 3 and 6.
3. **A creator tries to use a non-stock voice or look** (a crafted API call with a voice id outside the list). Refused by the edge function. Case in Phase 3.
4. **A long media job and the tab is closed.** The draft keeps its last good state, and the job is marked failed or resumable; no half file is published. Tests in Phases 3 and 5.
5. **A play-test or practice run.** Never written as progress or score (`test` flag). Cases in Phases 4 and 6.

# Phase 3: Voice and storage, then Slides and Podcast (release v0.12.0)

**Detailed plan written when Phase 2 ships.** Scope and fixed decisions:
- **Storage:** private bucket `media`, paths `userId/contributionId/...`, storage policies (owner writes own prefix, reviewers and learners read published via signed URLs), RLS cases. This also replaces the "photos in localStorage" shortcut later.
- **`voice` edge function** (copied from Horizon `server/voice.ts`):
  - ElevenLabs `with-timestamps`;
  - the key from the AI connection serving use `studio_voice` (kind voice);
  - voice id must be in `stock_voices` (an admin table: name, provider voice id, accent, language, active), else 422 (Review Focus 3);
  - ≤ 5,000 characters per call;
  - returns audio stored to the bucket plus marks;
  - daily character limit per use.
- **Browser fallback:** `speechSynthesis` with a watchdog (Taxatar `useSpeechSynthesis.ts`), labelled "Browser voice · not saved". Exports need a real voice.
- **Slides Studio:**
  - deck JSON `{slides: [{title, bullets, svg?, narration}]}` with marks (`narrativeText.ts`);
  - step player (`narrativeRun.ts`), audio per slide, CSS transitions (Calm or Camera flight as a simple translate);
  - export "Slides and audio" (stored files), "Video" via the Phase 5 compositor (deferred until then).
- **Podcast Studio:**
  - script with chapters and two voices;
  - TTS per turn in chunks;
  - playback stitches the stored segments in order, with chapter jumps and a transcript from the script;
  - ≤ 30 min;
  - mixing to one file is a shortcut for later (logged).
- The existing Podcast and Reel learner players (v3) read the new content shape, or a mapping keeps them working.

# Phase 5: Reel Studio (release v0.14.0)

**Detailed plan written when Phase 4 ships.** Scope:

# Phase 6: Avatar Studio (release v0.15.0)

**Detailed plan written when Phase 5 ships. Needs the owner's HeyGen contract and key first (S4).** Scope:
- **Authoring:**
  - Taxatar's character model (persona, situation, opening line, reveals if asked, hides unless probed);
  - learning points with weights (`parseLearningPoints`);
  - language, difficulty, feedback mode;
  - stock look (a HeyGen stock avatar id from an admin list) and stock voice.
- **Role-play runtime:**
  - persona prompt skeleton with STRICT RULES, version and hash (`personaPrompt.ts`), on `complete()`;
  - input and output guardrails (regex prefilter plus an LLM classifier; in-character substitute line);
  - browser speech-to-text (`useSpeechRecognition.ts`, push-to-talk).
- **`avatar` edge function** issuing short-lived HeyGen LiveAvatar tokens (key via AI connections, provider `heygen`). Live talking head (`useHeyGenAvatar.ts`, `ChromaKeyedVideo`, seconds metered).
- **Fallbacks (Review Focus 2):** portrait plus `voice`, or typing, at any time; "Switch to typing" always visible.
- **Scoring:**
  - Taxatar's rubric (evidence or ≤ 30, cited turns, strict JSON) with the creator's learning points;
  - the result is shown after the run; "AI scores, counsellor confirms" goes to the counsellor as the existing Avatar completion path.
- **Practice runs in the studio** never count (Review Focus 5).
- **Existing avatar learnings:** the scripted ones (`AVATARS`, L38–L41) keep working; studio-made scenarios use the new runtime.
- **Compliance notes to record:** HeyGen and ElevenLabs data retention terms (as Taxatar's subprocessor register), the "AI-generated" marking, and no recording of learner audio.
