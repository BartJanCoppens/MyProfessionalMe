# Studios Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the nine studios the v4 design shows next to the Flash card & Exam Studio: Avatar, Reel, Podcast, Game, Slides, Motion, Explainer, Job aid and Case. Reuse code and ideas from GameStudio, Horizon, Socials Reel Studio and Taxatar.

**Architecture:** One studio spine (`src/studioVals.ts` and `src/screens/Studios.tsx` from v4 Task 13) becomes data-driven:
- **Studio definitions.** Each studio is a definition: questions, an item schema, produce options, build steps and a preview kind.
- **What a studio makes.** Its output is a contribution that goes through the existing peer review and publishes into `learnings.content` (one new `kind` per studio).
- **Text.** All text AI goes through `complete()` and the `ai` edge function.
- **Media services.** Each sits behind its own edge function adapter, keyed through the existing AI connections (Vault, providers `elevenlabs` and `heygen`, use kinds `voice` and `avatar`).
- **Media files.** They go to one private Supabase Storage bucket.

**Tech Stack:** React 19, Vite, TypeScript, Supabase (Postgres, RLS, Storage, edge functions), Vitest, PGlite RLS runner.

**Spec:**
- The v4 design's `STUDIOS` block. Use its questions, items, rows and build steps per studio; names in examples become roles.
- The owner's answers of 17 Nov 2026:
  - Build the other studios, taking code and inspiration from the four projects (this reverses D1).
  - Voices: ElevenLabs with a browser-voice fallback, from an admin-approved list of stock voices.
  - Video: rendered in the browser.
  - Avatar practice: a live video avatar.
  - Order: cheapest first, one release per phase.

- Media limits (from the design): reel ≤ 90 s, podcast ≤ 30 min, motion ≤ 90 s, slides ≤ 15 min. Each TTS call ≤ 5,000 characters (chunk longer text).
- Migrations: new files only; never edit a pushed migration. Verify with PGlite; push to the live project with `supabase db push` at the end of each phase (owner's standing permission of 17 Nov 2026), then `npm run test:db` and advisors.

## Review Focus

1. **AI-generated SVG or game code carrying script or external loads.** Sanitised (SVG) or refused by the static scan, and sealed by CSP (games). Tests in Phases 2 and 4.
2. **A voice or avatar service is not configured or fails mid-way.** The studio says so and offers the fallback; nothing pretends to be the service. Tests in Phases 3 and 6.
3. **A creator tries to use a non-stock voice or look** (a crafted API call with a voice id outside the list). Refused by the edge function. Case in Phase 3.
4. **A long media job and the tab is closed.** The draft keeps its last good state, and the job is marked failed or resumable; no half file is published. Tests in Phases 3 and 5.
5. **A play-test or practice run.** Never written as progress or score (`test` flag). Cases in Phases 4 and 6.
6. **An untrusted `.horizon` file.** Any upload is refused before storage, with a reason, when:
   - it is over 50 MB, or not JSON;
   - it does not say `format: 'horizon'`;
   - its `version` is newer than the player supports.

   In the player:
   - Every SVG goes through `sanitizeSvg()` + `instance()`.
   - Calc `animation.code` is never executed (poster only).
   - Images and media must be `data:` URLs; any other URL is dropped.
   - Nothing calls Horizon's `/api/*` or any outside address (CSP for the player frame).

   Tests in Phase 3.

## Phase 4 tasks (written at the start of Phase 4, 18 Nov 2026)

**Decisions settled here** (from S6, S7, S11, the reuse map and the owner reuse rule; recorded in `decisions.md` at 4.6):
- **What a game is.** A Game is studio rows plus one built item. The rows are one `Concept` (text: the set-up; text 2: the win condition), at most one `AI role` (text: who the AI plays; text 2: what it knows and hides) and `Round N` rows (text: what the player sees; text 2: the answer). After them comes one game item `{kind: 'game', files: {'index.html', 'game.js'}, for: {role}, review: {passed, reasons} | null, made: 'ai'}`. `ITEM_MAX.Game` stays 10, so there are at most 9 rows.
- **Content from the rows, not from AI.** The game reads its content through `getData()`, which comes from the rows at publish time. Peer reviewers review exactly what plays, and editing a round needs no rebuild. GameStudio's AI "data" step is not ported. The build step "Writing the game content" turns the rows into the data, without AI.
- **Two files only.** `index.html` holds the markup and one inline `<style>`; `game.js` holds the logic. GameStudio's `style.css` is dropped. Caps: index.html ≤ 16,000 characters and game.js ≤ 32,000. They are sized so that a logic call that continues a file stays under the `ai` function's 60,000-character input cap: system + concept + index.html + the part written so far.
- **The hidden knowledge stays in the contribution.** The `AI role` row's text 2 stays in `contributions.items`, which learners cannot read (`contributions: read`: author, reviewers, System Admins). `learnings.content` carries `role: {kind, about}` without it. The `ai` function reads it with the service role through `contributions.learning_id`. GameStudio's `game_secrets` table is not ported, so the knowledge is never copied.
- **House rules.** The house rules are the `studio_game` use's instruction (`ai_uses.preamble`), which a System Admin edits on the AI connections page. GameStudio's `ai_settings`/`houseRules.ts` are not ported. The AI house-rules review is a build step on `complete()`. Its verdict is stored in the game item, so it is client-reported (logged as a PoC shortcut). The enforced gates are the static scan in SQL (check and submit), the frame's sandbox and CSP, and human peer review.
- **Completion stays as it is.** Game is a reflection format (`REFLECTION_FORMATS`, `private.evidence_rule`) and goes to the counsellor (functional design F2-a; `docs/product/functional-design.md` lines 160, 175, 218). Studio-made Games keep that rule. Playing or finishing a run never writes `learner_progress`. `record.sync.test.ts` stays unchanged.
- **Runs.** A run is on a published learning (`test = false`) or on a contribution (`test = true`: a play-test by its author or one of its reviewers). Leaderboards read finished non-test runs only, through one definer function (S11).
- **"My team only"** means the people who share your counsellor, that counsellor, and your own counsellees (`profiles.counsellor_id`). Listed as an owner question.
- **Port target.** Copied code goes to `src/game/` (player and bridge, like `src/horizon/`) and to `src/logic/` (pure rules). Nothing is imported from `/Users/comendacoppens/GameStudio` (S7).
