> **Status (17 Nov 2026):** waiting for the owner's answers to D1–D6 (Task 0). Parts A and D can start on the defaults; Part B needs D2 and D5; Part C needs D1.

**Goal:** Bring the app up to the 17 Nov 2026 design: seven new learning formats (Part A), certification trajectories with a credentials wallet (Part B), creation studios (Part C, scoped by D1), and two small mapping-screen changes (Part D).

**Architecture:** As in v3. Catalogue and trajectory definitions live in Supabase; pure rules go in small tested modules under `src/logic/`; each feature gets its own `*Vals.ts` view-model builder called from `Logic.renderVals()` (like `kbVals.ts`, `createVals.ts`), and its own screen file. Learner writes go through `persist()`; decisions about another person's progress go through `security definer` RPCs, like `decide_learning()`.

**Tech Stack:** React 19, Vite, TypeScript, Supabase (Postgres RLS, RPCs, edge function `ai`), Vitest, `npm run test:db`.

**Spec:** the Claude Design project `797ed301-7b6d-47eb-9e2d-6d7d2e7483c3`, now the claude.ai canvas "Learning Growth Development Platform" (https://claude.ai/artifact/VtxbG18GsoDAF34J9St5TW), page `MyProfessionalMe.dc.html`, version of 17 Nov 2026 (599,510 bytes). ## Global Constraints

- Business lines are `Consulting`, `Audit`, `Tax & Legal`. The design's props still say Advisory; never port it.
- Career stages are the app's seven (`STAGES`, `public.career_stage`). Never copy the design's five `STAGES`, `STAGE_FR` or `STG_SHORT`. Trajectory step windows are months, not stages.
- No fictional people (`src/logic/noPersona.test.ts` stays green). Not ported: "Thomas" (use the subject's real counsellor name, or "your counsellor" when there is none), "Lena", `PERSONAS`, `TEAM_TRJ0`, `CREDS0`, `ENROL0`, `ST_LOOKS` names, and sources "Peer · Yusuf Demir" (→ "Peer contribution") and "With Thomas De Smet" (→ "With your counsellor").
- Readiness counts accepted hours only. A trajectory step built on a learning is done only when that learning is `accepted` (the design also counts `submitted`; the owner's rule wins). Credentials never count toward readiness.
- Learners see published learnings only, and live trajectories only (plus any trajectory they are enrolled in).
- Ambition (`amb:`) and profile (`pro:`) audiences only ever suggest: a trajectory mapped there is never mandatory and never auto-enrols (same rule as `curriculum_mappings_advised_lenses`).
- Every new table: `revoke all … from anon, authenticated`, minimal grants, RLS on, one permissive policy per table and action, a case in `supabase/tests/rls.sql` per policy. Create migrations with `perl -e 'alarm 25; exec @ARGV' supabase migration new <name>`; push with `supabase db push`; run `supabase db advisors --linked`.
- Rules mirrored in code and SQL change together and are covered by `src/logic/record.sync.test.ts`.
- One AI path: `Logic.viaAi(use, …)` → `complete()`. Scripted output is never labelled AI. Prototype toasts from the design ("Prototype: opens the booking page…") are not shipped as if real: either the action does what it says or the button is not shown.
- Files stay under ~250 lines (UI ~220). `src/model.ts`, `Library.tsx` and `Map.tsx` are already over: new code goes into new files, not into them.
- Inline styles on DS tokens; match the design's pixel values. Respect `?motion=off` and `prefers-reduced-motion`.
- Done means `npm run build`, `npm run lint`, `npm test` pass, plus `npm run test:db` for every policy or grant change.

## Review Focus

1. **An admin reorders or removes trajectory steps after people have progressed.** Progress is keyed by a stable step id, never by position; a removed step drops out without errors and a moved step keeps its state. Test in Task 6 (`trajectoryProgress` after a reorder).
2. **A step's learning is submitted but not yet accepted.** The step shows "With your counsellor", not done, and the credential is not offered. Test in Task 6.
3. **A learner sets their own enrolment to `enrolled` on a "Counsellor approval" trajectory through the API.** Rejected. RLS case in Task 5.
4. **View as (read-only).** Start, ask approval, withdraw, request sign-off, book, flash-card ratings, exam answers and wallet additions are hidden or refused, and `persist()` writes nothing. Tests in Tasks 4 and 9.
5. **A step points at a learning that was unpublished or deleted.** The learner sees "No longer in the library" and the step does not block completion if it is optional; the admin editor shows a warning. Tests in Tasks 6 and 8.

Defaults apply if the owner accepts them; record each answer in `docs/decisions.md` and in `docs/product/user-journeys-and-epics.md` §7.

- [ ] **D1 Studios (Part C).** The design adds ten studios, including Avatar, Reel, Podcast, Slides and Motion, which need voice, video and avatar generation the app does not have; the avatar studio is parked for Taxatar. *Default:* build only the Flash card & Exam studio (text only, through `complete()`), keep the upload form, park the other nine.
- [ ] **D2 Who publishes a mandatory trajectory (Part B).** The design says "Learning Council sign-off"; the app has no council. *Default:* a System or General Admin publishes it; a Domain Admin can publish advised trajectories for their own line only. The warning text says "needs a System or General Admin to publish".
- [ ] **D3 Completion of the new formats (Part A).** *Default:* Flash cards, Job aid and Practice exam complete themselves (whole deck reviewed once; all items ticked; one finished round); Teach-back completes itself once an explanation is sent (the score is advice); Webinar completes like Classroom (attendance or feedback form); Case exercise and Stretch assignment go to the counsellor, with a link to the deliverable (Case) or a reflection of at least 140 characters (Stretch).
- [ ] **D4 Practice-exam readiness bar.** The design uses 70 % ("Ready to book the real exam"). *Default:* keep 70 %, as advice only; it never locks the exam step.
- [ ] **D5 How a trajectory ends in a credential (Part B).** The design adds it "once the issuer confirms". *Default:* the learner submits the exam result with a certificate link or number (the existing Certification evidence rule); the counsellor accepts; the credential appears in the wallet with its expiry from "valid for". External credentials follow the same path and stay "Waiting for your counsellor" until confirmed. Links only, no uploads (as `LINKED_NOT_UPLOADED`).
- [ ] **D6 Auto-enrol start date.** *Default:* someone in an auto-enrol mandatory audience is enrolled without a row; their start month is the later of the trajectory's publication and the month they joined that audience's stage. A row is written at their first action.
