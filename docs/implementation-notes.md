# Implementation notes (reference)

Feature-by-feature file maps and database rules, moved out of the AI instruction file (`AGENTS.md`). Version tags and owner answers are history; the code and migrations are the source of truth.

## Screens and view-models

- Podcasts and reels (design v3): `MEDIA` in `src/data.ts` holds each one's player content (host, length, chapters or captions and question); `src/logic/media.ts` the playback and save rules; `Logic.tick()` / `mediaVals()`; `App` runs one 250 ms clock while something plays. A podcast completes itself at 80% listened and a reel on a right answer (owner, Q3): the database allows the owner to set `accepted` for a published learning of a self-completing format (`private.is_self_complete`; see Completion per learning type). A podcast or reel without `MEDIA` content shows its cover but no player.
- Knowledge library (admin, design v3): `src/kbVals.ts` builds `vm.kb` (null off-screen), `src/screens/Knowledge.tsx` renders it, `src/logic/okf.ts` holds retrieval (never reads client or licensed sources), OKF v0.2 files, import and the tar download. Bundles are stored per business line (`knowledge_bundles.business_line`, null = firm-wide); edits save shortly after each change. The full design export lives in `Design/` (git-ignored; the design tool's reader stops at 256 KB).
- Create & share (design v3, F12): `src/createVals.ts` builds `vm.create` (null off-screen) and `vm.reviewBadge`; `src/screens/Create.tsx` renders the tabs Mine, Review for peers, New content and, for admins, Review requirements; `src/logic/contribution.ts` holds the pure rules (`ruleMatches`/`mayCreate`, `allowedValues`, `ruleSentence`, strictest `policyFor`, `contentChecks`, `rubricComplete`, `stagesFor`/`stagesOf`, `reviewBadge`); `src/lib/contributionStore.ts` the Supabase calls. "Ground it in firm knowledge" never lists every bundle (there may be hundreds): picked bundles are chips, and `findBundles` (createVals.ts) returns at most five to add, by search or else ranked against the piece's title and domain, else the most used. `AppState.create` is the signed-in person's own work (`access.userId`, not the subject), loaded by `App` and reloaded after every write. User management has the "Can create for" drawer (creation rules, four-part chip editor `src/screens/RuleChips.tsx`, also used by Review requirements) and, for System Admins, a Domain experts tab (several experts per domain, add and remove).
- Learning record and approvals (F2, F3, v0.7.0): `src/recordVals.ts` builds `vm.rec` (the detail's evidence form or read-only evidence, open feedback, acceptance record, decision box) and `vm.appr` (the "Waiting for you" queue, null off-screen) plus `vm.approvalsBadge`; `src/screens/Approvals.tsx` renders the queue; `src/logic/record.ts` holds the pure rules (`evidenceRule` per format, `evidenceProblem`, `openChanges`, `decisionLine`, `workingDaysSince`, `lastActivityLabel`); `src/lib/recordStore.ts` calls `decide_learning` and `waiting_submissions`. Evidence is text on the progress row (reflection, link, certificate number; files are linked, never uploaded) and goes through `saveProgress` / `save_learning`. `AppState.queue` is the signed-in person's (not the subject's), loaded by `App` and reloaded after every decision and on opening the screen. Decisions are not learner writes: they bypass `persist()` and work in View as; evidence and submit go through `persist()`. My team shows each counsellee's last activity (latest `learner_learnings.updated_at`).
- Completion per learning type (v0.7.2): `src/completionVals.ts` builds `vm.done` (`kind`, `note`, and per format `mark` for E-learning, `feedback` for Classroom, `quiz` for Avatar, plus `attendance`, the admins' Attendance card on a classroom); `src/screens/Library.tsx` renders them on the detail (`QuizCard`, `FeedbackCard`, `AttendanceCard`); `src/lib/attendanceStore.ts` calls `attendance_roster` and `register_attendance`. `AppState.fbDraft` and `quiz` are keyed `subject|learning`; `AppState.att` is the signed-in admin's roster, loaded by `openDetail` for admins on a classroom and reloaded after a registration. The avatar quizzes are `AVATAR_QUIZ` in `src/data.ts`.
- `supabase/migrations/`: `profiles`, `user_roles`, RLS, private helper functions, first-admin bootstrap. `supabase/functions/manage-users/`: create / remove / reset password / change own password via the auth admin API.
- AI connections (System Admin only): `src/aiVals.ts` builds `vm.ai` (null off-screen and for every other role) plus `showAi`/`navAi`/`goAi`; `src/screens/AiConnections.tsx` renders it; `src/logic/ai.ts` holds providers per kind, `statusOfUse()` (Live / Scripted · why / Waiting for …) and the form checks; `src/lib/aiStore.ts` the Supabase calls; `src/lib/ai.ts` is `complete()`, the one AI path (see Assistants). `supabase/functions/ai/`: `index.ts` (auth, roles, limits, Vault key) over `core.ts` (pure: request caps, provider request, reply parsing, preamble order; tested by `src/lib/aiCore.test.ts`). `scripts/rls-pglite.mjs` stubs Vault (`SHOW=AI` prints those checks).

## Accounts, access and database rules

- Acceptance (F2): the counsellor, a managing Domain Admin, a General or a System Admin decides, never the person (`private.can_accept`), only through `public.decide_learning(user, learning, 'accepted'|'changes', comment)` (security definer): accept, or request changes with a 10–500 character comment, which puts the learning back to in-progress (pct kept) for the learner to resubmit. It writes `learning_decisions` (who, name as it was, when, verdict, comment, evidence snapshot); learners have no write grant there. A learning completing itself is recorded as `self_completed` by a trigger (with the classroom feedback as its evidence). The evidence rule per format is `private.evidence_rule` (mirrored by `evidenceRule` in `src/logic/record.ts`; change both): Certification needs a link or certificate number; Book, Website, Mentoring, Coaching, Game, Micro-guide and Case write-up a reflection of at least 140 characters; the rest nothing. Triggers check it whenever the learner submits or edits a submission's evidence, stamp `submitted_at`/`updated_at`, freeze an accepted learning's evidence, and keep accepted items accepted. `public.waiting_submissions()` is the queue: counsellees' submissions plus, for anyone who may accept, those of people without a counsellor. Keep one permissive policy per table and action (merge with OR).
- Completion per learning type (owner, 2 Nov 2026; v0.7.2): Podcast (80% listened), Reel (a right answer), E-learning ("Mark as completed"), Avatar (three right answers in the evaluation quiz after the practice session; trust-based like reels) and Classroom complete themselves, without a counsellor: `private.is_self_complete()` lists these formats (published only). A Classroom completes when the learner sends the feedback form (rating 1–5 in `learner_learnings.evidence_rating`, "What will you apply?" of at least 40 characters in `evidence_note`; the record trigger refuses the learner's completion without it, `private.completion_rule()`/`completion_ok()`), or when the faculty registers attendance: `public.register_attendance(learning, user_ids)` (security definer; published Classroom only; all or nothing; faculty = `private.can_register_attendance()`: a Domain Admin for people they manage, a General or System Admin, never the person themselves) sets `accepted` with pct 100 and records verdict `attended`; an accepted item stays accepted. `public.attendance_roster(learning)` lists whom the caller may register. Every other format goes to acceptance with the evidence rule above. The app never offers "Ask … to approve" for a self-completing format (the database still accepts such a submission, so older ones keep waiting). The rules are `COMPLETION`, `FEEDBACK_MIN`, `REFLECTION_FORMATS`, `CERTIFICATE_FORMATS` in `src/logic/record.ts`; `src/logic/record.sync.test.ts` compares them with the latest migration, so change both together.
- Certification trajectories (design v4, part B; migration `20261117170000_trajectories.sql`). Three tables:
  - `trajectories` (ids `T1`–`T3` seeded from the design, new ones `T100`… from `trajectories_seq`): name, issuer, credential, enrol (`auto`/`open`/`approval`), months, valid_months (null: no expiry), renewal, cost, status (`draft`/`live`/`retired`), business_line (null: firm-wide), steps, maps, published_at (stamped the first time it goes live), updated_at. `steps` is an array of `{id, k: learn|elect|evidence|check|exam, lid?, opts?, pick?, title?, hours?, win, req, pre: stepId|null}`; the database checks only unique string ids and the kind (`private.trajectory_steps_ok`), the rest is checked in TS. `maps` is `[[audience, stage, mandatory|advised], …]` with the `curriculum_mappings` audience rule, a `career_stage` value, and `mandatory` only on a business-line audience (`amb:`/`pro:` only advise; `ind:`/`tec:` membership is not stored) (`private.trajectory_maps_ok`). Read: live ones by everyone signed in, drafts and retired ones by the line's content editors and by whoever can read an enrolment row on it. Write: `private.can_write_trajectory(line, status, maps)` = `can_edit_content(line)` and `can_edit_audience` for every mapped audience (as curriculum mappings), and a live trajectory with a mandatory map only by a System or General Admin (owner decision D2), so a Domain Admin cannot publish, edit, take back or delete one.
  - `trajectory_enrolments` (pk user, trajectory): status `requested`/`enrolled`, `start_month` (year*12 + month index), `steps` jsonb keyed by step id (`{state: submitted|booked|done, link?, ref?, note?}`, evidence, check and exam steps only; learning and elective steps are done when their learning is accepted), asked_at, decided_by, decided_at. Read through `private.can_view_track` (the person, counsellor, managing admins, General Admins); no write grant: everything goes through the functions below. An `auto` trajectory binds only people inside one of its mandatory maps (business line and career stage, `private.in_mandatory_audience`): their row is written at their first action, starts in the publication month and cannot be withdrawn (D6, see `docs/decisions.md`); for everyone else it behaves like `open`. A retired trajectory still lets enrolled people finish and earn the credential (the learner functions and `decide_trajectory` do not check status).
  - `credentials`: name, issuer, earned_on, expires_on, link or certificate number (one is required; links only), trajectory_id, status `waiting`/`confirmed`, confirmed_by/at. Read through `can_view_track`; the learner inserts only their own `waiting` row (column grant without status, trajectory or confirmation).
  - Functions (security definer): `request_trajectory(id)` (live only; `enrolled` for open and auto, `requested` for approval; asking again changes nothing), `withdraw_trajectory(id)` (deletes a requested row, or an enrolled one without a done step; never a mandatory auto-enrol one), `submit_trajectory_step(id, step, state 'submitted'|'booked', link, ref, note)` (evidence/check/exam only, booked for an exam only, an exam result needs a link or number and evidence a link or note, never on a submitted or done step, so the counsellor decides on what they saw; writes the enrolled row for a mandatory auto-enrol trajectory), `decide_trajectory(user, id, step|null, 'approve'|'talk')` (by `private.can_accept`, as `decide_learning`: a null step approves a start request, and `talk` leaves it waiting, stamped; a submitted step becomes done, and `talk` removes it so the learner resubmits; accepting the exam inserts the confirmed credential with expiry from valid_months, D5, and is refused while the person holds a valid confirmed credential from the same trajectory; the guard allows another credential after expiry, but there is no re-take path yet: a signed-off exam step cannot be submitted again), `confirm_credential(id)` (by `can_accept`).
  - Learner side: library cards, the trajectory page (screen `trajectory`, AppState `trjView`/`trjOrigin`), the credentials wallet in My profile and the practice exam's "Open the trajectory" link. View-model `src/trajectoryVals.ts` (cards, exam link), `trajectoryPage.ts`, `walletVals.ts`, shared `trajectoryCtx.ts`; screens `Trajectory.tsx`, `Wallet.tsx`; pure rules `src/logic/trajectoryLearner.ts` (effective enrolment, `canWithdraw` mirrors `withdraw_trajectory`, `stepAction`, `credentialLook`). The subject's enrolments and credentials are in `trjMine` (loaded in `App.tsx` when the subject changes, reloaded after every action; data for another person is never shown). A mandatory auto-enrolled person is enrolled without a row; their first step action writes it. Every write goes through `Logic.persist`, so View as refuses it and renders no action. "Book the exam" only records `booked` (no external call).
  - Admin editor (Curriculum mapping, tab "Certification trajectories"): view-model `src/trajectoryAdminVals.ts`, screens `src/screens/TrajectoryEditor.tsx` and `TrajectoryMapping.tsx`, pure rules `src/logic/trajectoryEdit.ts` (new trajectory, step ids `s<n>`, add/move/remove, `addMap`) and `trajectoryView.ts` (labels, learner's-eye stones). Trajectories are in AppState `trjs` (loaded once in `App.tsx`); every edit updates them at once and `saveTrajectorySoon` writes the latest version; `+ New` inserts a draft at once. The UI mirrors `can_write_trajectory` (`refusal()`): a Domain Admin sees only their line's trajectories, the audience list holds only audiences they may edit, and Live is disabled (and refused) while a map is mandatory. A trajectory with an empty name or credential stays on screen but is not saved (the database refuses it), and no other edit to it is saved meanwhile; the editor shows "Not saved until it has a name and a credential." as its first warning. New step ids are `s` + time + two random characters (never derived from the current steps, so a removed step's id is never reused); seeded ones stay `s1`… The coverage grid shows ◆n per cell: live and draft trajectories this admin sees, mapped to that audience and stage.
  - Counsellor side: My team tab "Certifications" (`src/screens/TeamTrajectories.tsx`, view-model `src/teamTrjVals.ts`). `useTeam` loads each counsellee's enrolments and credentials with the team (`Member.trj`) and `refresh(personId)` reloads one person after a decision. "Waiting for you" lists `requested` starts and `submitted` evidence/check/exam steps with the learner's proof; Approve/Sign off and Talk first call `decideTrajectory` through `Logic.persist` (no buttons in View as). Talk first keeps no session marker: the database leaves a start requested or clears the submitted step. The table shows required-step progress and Needs approval / Needs sign-off / On track / Credential earned (confirmed credential). The mapping's person zoom lists `personTrajectories(...)` lines under `pz.trjRows`. Waiting credentials appear as "Credential" rows with Confirm (`confirm_credential`).
- Nobody but a System Admin may manage a person who is Domain Admin for a line the caller does not administer (`private.can_manage_user` and `manage-users` both enforce it).
- Create & share rights are rules (`creator_rules`): four parts (lines, formats Reel/Podcast/Micro-guide/Case write-up/Flash cards/Practice exam, domains, `ind:`/`tec:` audiences); OR within a part, AND across the filled parts, an empty part = any (any of the three lines; never firm-wide); several rules of a person are OR. "(Consulting OR Tax & Legal) AND Podcast" = `{lines: [Consulting, Tax & Legal], formats: [Podcast]}`. System and General Admins grant anyone any rule; a Domain Admin only to people they manage and only with a filled lines part inside their own lines (`private.can_grant_rule`). A contribution states its line (always one; default the author's), format (its type), domain and an optional audience; some rule must match on insert, update, submit and again at publication (`private.may_create`, `rules_allow`, `rule_matches`), and the four lock after the first submit. `review_policies` use the same four parts plus peers 0..2, expert, quality; every matching one applies and the strictest wins (`private.policy_for`; a contribution without an audience also gets the audience-scoped ones); none = 2 peers, expert, quality & risk; Domain Admins set them only within their lines (`private.can_set_policy`). Status, steps and verdicts change only in `private.submit_contribution` / `review_contribution` / `publish_contribution` (security definer, called through `public.submit_contribution` and `public.review_contribution`); guard triggers check the transition shapes. Peer reviewers come from the author's line or the content's line (`private.peer_candidates(author, line)`), never the author, their counsellor or their counsellees; each person reviews one step. Routing: one of the domain's experts (`domain_experts`, several per domain, kept by System Admins; `private.pick_expert`: never the author, fewest open reviews) or a System Admin, a General Admin or a System Admin for quality & risk, then peers from the author's line, never the author, their counsellor or people they counsel, and one step per person. Too few people refuses the submit (still a draft). A resubmission runs the whole flow again. Client names are checked in every text field (`CLIENT_WORDS`, mirrored in `private.blocked_term`). The last approval inserts a `learnings` row (`source 'Peer contribution'`, the contribution's line, `created_by` the author); colleagues read that row, not the contribution. Ambitions and interests are never used for routing. No media storage yet: a contribution is text only. Flash cards and practice exams carry `contributions.items` (cards `[front, back]`, questions `{t, q, o[4], a, why}`; shape checked by `private.items_ok` at submit and mirrored in `src/logic/items.ts`); `src/createItems.ts` and `src/screens/CreateItems.tsx` draft, import (CSV) and show them, a submit without items is refused, and `private.publish_contribution` writes them into `learnings.content` (`flash` / `exam`).
- AI connections and uses are System Admin only, reading included (`ai_connections`, `ai_uses`, RLS on `private.is_system_admin()`). A key goes into Supabase Vault only through `public.ai_set_key()` (System Admin); the table keeps `secret_id` (not granted to clients) and `key_hint` (last 4). Only `public.ai_connection_key()` returns a key, and only to `service_role` (the `ai` function). Deleting a connection deletes its secret. A use takes only a connection whose provider fits its kind (`private.ai_provider_fits`: text = anthropic / openai_compatible, embedding = openai_compatible / other, voice = elevenlabs / other, avatar = heygen / other). `public.ai_live_uses()` (any signed-in user) returns the use keys that are enabled, text, not waiting for a feature, with a connection that has a key and a model; the app and the function both go by it. `ai_usage` (no client access) is counted by `public.ai_count_call()` (service_role) up to `ai_uses.daily_limit` per person per day (UTC); `public.ai_usage_summary()` gives the System Admin calls per use and the top users, never content.

## Assistants (AI)


Six text uses can be answered by AI: the profile chat ("Talk it through", use `profile_chat`), the curriculum copilot (`curriculum_copilot`), "Read it as …" in the learner's eye (`learners_eye`), the Knowledge library's test retrieval answer (`kb_answer`) Create & share's "Draft with AI" (`draft_outline`) the items of flash cards and practice exams (`draft_items`, off until a System Admin switches it on; cards fall back to a scripted draft from the passages labelled "Scripted from the bundle", exam questions only by CSV import) and the teach-back check (`teach_back`, off until a System Admin switches it on; its scripted fallback is `teachCheck`, labelled "Checked by keyword"). All go through `Logic.viaAi(use, request, parse)` → `complete()` in `src/lib/ai.ts`, in this order: `window.claude.complete` inside Claude Design; else the `ai` edge function when the use is in `AppState.aiLive` (from `ai_live_uses()`, loaded once by `App` and after every change on the AI connections page); else null, and the caller uses its scripted reply (`Logic.scripted()`, `scriptedCp()`, `scriptedRead()`, the top passages in `kbVals.ts`, the scripted outline in `draftFromPassages`). `?live=off` forces scripted. A failure never falls through to another source.
- Labels never call scripted output AI: `Logic.aiLabel(use)` is "AI assistant" only when AI would answer and the last attempt did, otherwise "Scripted assistant" (or "… · AI did not answer"); reads carry `ai`, the test answer has `kbAnswerNote`, and only an AI outline is saved as `ai_assisted`. A reached daily limit shows as a toast, then the scripted reply.
- The `ai` function: `{ use, system?, messages, max_tokens? }` from any signed-in user (admins-only uses need an admin role) → `{ text }`; `{ action: 'test', connection_id }` for System Admins → `{ ok, model }` or `{ ok: false, error }`. It sends the use's fixed instruction (`ai_uses.preamble`) first and the app's system text after it, caps `max_tokens` (1024; Anthropic gets at least 4096 because thinking counts toward it), messages and size, counts the call before making it, scrubs the key from errors and logs only use, outcome and duration. Providers: Anthropic Messages API (`anthropic-version: 2026-10-21`), or OpenAI-compatible `/chat/completions` at a base URL (OpenAI, Azure OpenAI, EU services such as Mistral). The EU route is the owner's choice of connection, not code: Anthropic's direct API offers global or US processing only. Voice, avatar and embedding uses only store a connection until their feature exists (`waiting_for`). Never put an API key in the client bundle.
- v4 formats (design v4): `src/fmtVals.ts` builds `det.fl|ex|ce|tb|sa|wb|ja` (null without catalogue `content`), `src/fmtStudy.ts` the study panels (flash, exam, teach-back), `src/fmtCover.ts` the cover lines (merged in `Logic.items()`), `src/fmtShared.ts` the session draft (`AppState.fmt`, per subject and learning) and `saveDetail()`; `src/screens/FormatPanels.tsx` and `FormatWork.tsx` render them, `Cover.tsx` draws the covers. Flash, exam, teach-back and job aid complete themselves through `saveProgress` (state accepted); case and stretch use the evidence flow (`submit`); webinar uses the classroom feedback card. The 70 % exam verdict is advice only.
